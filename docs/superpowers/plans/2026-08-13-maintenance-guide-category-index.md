# 维护手册按问题类型分类索引实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 superpowers:executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）跟踪进度。

**目标：** 保持第 22 节正式台账原始时间顺序，在维护手册中新增可验证的按问题类型分类索引和稳定锚点。

**架构：** 分类索引作为第 22 节的导航层，放在记录模板与首条正式记录之间；历史正文仍是唯一事实源。每条正式记录前增加唯一 ASCII HTML 锚点，索引允许多分类引用，并通过 PowerShell 文档断言验证顺序、覆盖和链接完整性。

**技术栈：** Markdown、HTML anchor、PowerShell、Git。

---

### 任务 1：建立历史顺序与分类映射基线

**文件：**
- 修改：`docs/system-maintainer-onboarding-guide.md`

- [ ] **步骤 1：读取第 22 节所有正式记录标题并保存原始顺序**

运行：

```powershell
rg -n '^### 20[0-9]{2}-[0-9]{2}-[0-9]{2} — ' docs/system-maintainer-onboarding-guide.md
```

预期：输出设计规格列出的现有正式记录，顺序与修改前一致。

- [ ] **步骤 2：为每条正式记录设计唯一锚点**

锚点严格使用设计规格中的 `change-YYYY-MM-DD-topic` 格式，同日记录不得重复。

- [ ] **步骤 3：建立问题类型到记录锚点的完整映射**

按规格第 6 节归类，每条历史记录至少进入一个分类；允许重复归类，不复制正文。

### 任务 2：实现分类索引和稳定锚点

**文件：**
- 修改：`docs/system-maintainer-onboarding-guide.md`

- [ ] **步骤 1：在记录模板后增加“按问题类型分类索引”**

为 11 个分类分别创建表格：日期、记录、状态。状态只能使用规格规定的有限词汇或“状态见原记录”。

- [ ] **步骤 2：在每条正式记录标题前增加显式 HTML 锚点**

示例：

```html
<a id="change-2026-08-05-daily-maturity-window"></a>

### 2026-08-05 — 权威日报自动尝试窗口调整为业务日结束后五小时
```

- [ ] **步骤 3：追加本次分类实施台账**

记录目标、原因、分类方案、影响范围、顺序保护、验证、审阅、Git 和发布状态。该记录本身也必须有锚点并进入分类索引。

### 任务 4：运行文档结构验证

**文件：**
- 验证：`docs/system-maintainer-onboarding-guide.md`
- 验证：`docs/问题记录.md`

- [ ] **步骤 1：验证历史标题顺序未变**

运行 PowerShell 提取修改后正式标题，与任务 1 保存的原始标题数组逐项比较。

预期：数量相同、每个原有标题位置相同；仅允许本次新记录追加在末尾。

- [ ] **步骤 2：验证锚点唯一性和链接完整性**

解析所有 `<a id="...">` 和索引链接 `](#...)`：

- 锚点无重复；
- 每个索引链接存在对应锚点；
- 每个正式记录前存在一个锚点；
- 每个正式记录至少被索引一次。

- [ ] **步骤 3：验证分类和状态词汇**

断言 11 个分类标题全部存在；状态只使用批准词汇。

- [ ] **步骤 4：运行差异和敏感信息检查**

```powershell
git diff --check
```

并扫描已知秘密字面量；预期均通过。
