# 新服务器直接采集迁移设计

## 决策

自 2026-08-01 起，新服务器承担控制面、OAuth 凭据、采集调度和 Google Ad Manager 采集运行时。旧服务器仅作为迁移前数据来源和可回退环境，不再接收新采集任务。

## 原因

旧服务器根分区接近满载，内存和 swap 均处于压力状态；继续承担采集会提高失败和数据损坏风险。保留旧节点采集则要求跨节点调度、结果回传和多套状态一致性，且已发现自动路径会发生双重采集。

## 目标架构

```text
操作端 -> 新服务器控制面 -> 新服务器采集运行时 -> Google Ad Manager
                         -> 新服务器 control_plane.db

旧服务器 -> 保留原库、节点服务和备份，仅供回退；不启动新的中台采集任务
```

## 切换顺序与门禁

1. 新服务器服务保持停止，部署目标提交，环境变量使用生产 SQLite 路径，并将 `ADX_COLLECTOR_DIRECT_COLLECTOR_ONLY=true`。
2. 在旧服务器停止旧中台和所有旧采集触发器后，执行 WAL checkpoint；校验后复制数据库并在新服务器校验哈希和 SQLite 完整性。
3. 新库先执行 Alembic 升级，再导入和加密 OAuth 凭据；迁移过程禁用所有计划任务。
4. 启动新服务但保持调度禁用，逐账号验证 OAuth、代理出口、一次手工采集、报告落库和任务状态。
5. 按账号灰度启用计划任务；稳定观察后停止旧中台采集触发器。旧数据和旧节点服务不删除。

## 运行时约束

- 新服务器只允许 `direct_collector_only=true`；调度、手工拉取、OAuth 恢复和灰度日报均由新服务器采集运行时执行。
- 旧节点的 `/ke/*`、回调域名和 MySQL 不作为新中台采集依赖；Cloudflare 回源调整不构成新机采集的上线条件。
- 切换前不得启动新服务的 scheduler；切换后也只能在 OAuth 健康、单账号手工采集成功且无进行中旧任务时启用。
- 回滚仅将流量和计划切回旧中台；不得用旧库覆盖新库，必须保留新库副本以审计迁移后写入。

## 验收标准

- 新服务器采集进程不访问旧节点的 fetch/report 接口。
- 每次自动任务只能启动一个新服务器采集运行时。
- 新服务器单账号手工采集成功并生成对应任务和报告；失败时不启用该账号计划。
- 数据库哈希、SQLite integrity check、schema revision、OAuth 迁移统计均有维护记录。
